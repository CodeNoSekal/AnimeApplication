# Технический аудит Yume

Дата полной проверки: 13 августа 2026 года.

Этот документ — постоянный список найденных проблем и план исправлений. Он проверяется и обновляется после каждого этапа работ. Из области аудита по просьбе владельца исключена подпись приложения.

Статусы:

- `[ ]` — предстоит исправить;
- `[~]` — исправление начато;
- `[x]` — исправлено и проверено.

## P0 — критические ошибки

- [x] Синхронизировать состояние сессии после неудачного обновления токена. Общий `AuthSessionManager` атомарно обновляет токены и `SessionState`; подтверждённый отказ refresh немедленно переводит корневой UI в `Unauthenticated`.
- [x] Устранить ошибочные родительские маршруты в разделе коллекций: `CollectionsGraph` открывает детали и поиск с контекстом `COLLECTIONS`.
- [x] Передавать фактический родительский экран в `SearchComposable`; карточка из поиска сохраняет контекст своего графа.
- [ ] Подключить рабочий экран поиска в `SearchGraph`. Сейчас импортирован одноимённый экран-заглушка из `presentation.screens`, а реализованный поиск находится в `presentation.screens.search`.
- [x] Защитить плеер от пустых источников и озвучек. Единый `resolvePlayback` безопасно обрабатывает отсутствие эпизодов, источников, озвучек и URL, ищет воспроизводимую альтернативу и возвращает типизированную ошибку вместо исключения.
- [ ] Запретить выбор недоступных серий и показывать их состояние в `EpisodesPicker`.
- [x] Исправить переходы между сериями: переходы и доступность кнопок вычисляются по положению текущей серии в фактическом списке `episodes`, поэтому разрывы в нумерации обрабатываются корректно.
- [x] Устранить гонку сохранения прогресса плеера. `PlaybackContext` привязывает позицию к конкретному `MediaItem`, а `ProgressSaveQueue` отправляет неизменяемые снимки прогресса строго последовательно и не позволяет старому запросу завершиться после нового.
- [x] Сделать безопасными персонализированные и остальные nullable-поля DTO: отсутствующие `favorite`, `my_status`, `my_score`, заголовки, постеры и другие необязательные значения получают корректные значения по умолчанию.
- [x] Развести DTO прогресса и доменную модель по nullable-полям: `sourceProvider`, `voiceoverId`, заголовок и постер допускают отсутствие в ответе.
- [x] Обрабатывать ошибки JSON/несовместимой схемы ответа: обычные запросы возвращают типизированную ошибку, Paging — `LoadResult.Error`, отмена coroutine при этом не проглатывается.

## P1 — высокая важность

- [x] Не использовать `runBlocking` для чтения DataStore на каждом сетевом запросе в `AuthInterceptor`. Актуальная пара токенов хранится в volatile-снимке `AuthSessionManager`, загружается при проверке сессии и атомарно обновляется при входе/refresh/выходе.
- [x] Исключить пароли, коды, access/refresh-токены и тела приватных запросов из логов: debug-логирование ограничено методом/URL и кодом ответа, чувствительные заголовки редактируются, логирование тела ошибок удалено.
- [x] Не проглатывать `CancellationException` в репозиториях, PagingSource, authenticator и очереди прогресса.
- [x] Возвращать вызывающему коду `OperationResult` из `putProgress`, `sendCode` и `logout`; ошибки обрабатываются ViewModel или очередью.
- [x] Исправить классификацию неверного проверочного кода: ответы 400/422 из verify превращаются в `IncorrectCode`.
- [x] Защитить формы входа и подтверждения от двойной отправки: `isLoading` устанавливается синхронно до запуска coroutine.
- [x] Сериализовать изменения избранного и статуса на экране деталей и обновлять состояние только по завершении соответствующего запроса. Визуальная блокировка не добавлялась, поскольку UI исключён из текущего этапа.
- [ ] Добавить retry-действие на корневой экран ошибки; метод `RootViewModel.retry()` сейчас недоступен пользователю.
- [ ] Реализовать понятные loading/error-состояния в `DetailsComposable` и `PlayerGraph`; пустой экран не должен быть конечным состоянием.
- [ ] Показывать текст реальной ошибки и навигационные действия в `ErrorScreen`.
- [x] Исправить обновление главного экрана после возврата: загрузка запускается при фактическом появлении Home, а прежний запрос перед переходом удалён.
- [ ] Показывать кнопку просмотра только при наличии поддерживаемого источника (`hasKodik`/`hasLibria`), предварительно сохранив эти поля при маппинге ответа.
- [ ] Показывать ошибки и повтор загрузки в Paging-списках: initial load, append, refresh и пустой результат.
- [ ] Отображать `ProfileUiState.error` и давать повторить загрузку профиля.
- [x] Обрабатывать `C.TIME_UNSET` и отрицательные значения до сохранения/форматирования времени плеера.
- [x] При выходе из плеера восстанавливать предыдущую ориентацию Activity, а не всегда принудительно portrait. Исходное значение сохраняется и восстанавливается в `PlayerReleaseEffect`.
- [x] Заменить `popUpTo(0)` явным корневым маршрутом `Destinations.ROOT`.

## P2 — сборка, зависимости и ресурсы

- [ ] Включить R8 и resource shrinking для release после добавления правил и регрессионных тестов. Текущая release-сборка имеет `isMinifyEnabled = false`.
- [x] Согласовать JVM toolchain: Java и Kotlin используют 17.
- [x] Удалить дубли Compose-зависимостей: компоненты используют один BOM без параллельных фиксированных алиасов UI/Material 3.
- [x] Проверить и удалить неиспользуемые прямые зависимости: Room и его plugin/compiler, Security Crypto, AppCompat, Image Cropper, Google Fonts, Media3 Views UI, runtime tracing и неиспользуемый Turbine удалены. Material Views оставлен, потому что XML-тема наследуется от `Theme.Material3.Dark.NoActionBar`.
- [x] Исследовать предупреждение Moshi codegen о deprecated KAPT: процессор загружен задачей KSP, а `debugAnnotationProcessor` пуст; предупреждение выводит Hilt после обработки сгенерированных Java-классов и не указывает на фактическое подключение KAPT в проекте.
- [ ] Разобрать 73 неиспользуемых ресурса из lint: не удалять автоматически, а сверить с планируемыми экранами.
- [x] Устранить 18 конфликтов XML/PNG: все 450 density PNG удалены, а код переведён на канонические vector drawable `_24` с сохранением прежних размеров через `Modifier.size`/компоненты.
- [x] Удалить девять групп PNG с идентичным содержимым. В исходных ресурсах и остальном репозитории вне генерируемых каталогов PNG больше нет.
- [ ] Выбрать единый источник дизайн-токенов: сейчас цвета/размеры частично дублируются между XML и Compose.
- [ ] Обновлять AGP, Kotlin, Compose, Hilt, Media3, Paging и AndroidX небольшими отдельными шагами с тестами, а не одним массовым изменением.
- [x] Шифровать токены авторизации на устройстве, сохранив перенос сессии на новое устройство: `TokenCipher`/`TokenStorageImpl` шифруют access/refresh токены (AES-256-GCM), ключ хранится в том же DataStore-файле и переносится вместе с ним. `backup_rules.xml`/`data_extraction_rules.xml` больше не исключают `auth_prefs.preferences_pb` ни из резервного копирования, ни из `device-transfer`, поэтому сессия сохраняется после переноса/восстановления. Компромисс: схема защищает от изолированного чтения одного значения, но не от копирования файла целиком вместе с ключом — аппаратный (Keystore) ключ дал бы более сильную защиту ценой потери переносимости.
