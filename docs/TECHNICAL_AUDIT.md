# Технический аудит Yume

Дата полной проверки: 13 августа 2026 года.

Этот документ — постоянный список найденных проблем и план исправлений. Он проверяется и обновляется после каждого этапа работ. Из области аудита по просьбе владельца исключены подпись приложения и шифрование токенов авторизации.

Статусы:

- `[ ]` — предстоит исправить;
- `[~]` — исправление начато;
- `[x]` — исправлено и проверено.

## P0 — критические ошибки

- [x] Синхронизировать состояние сессии после неудачного обновления токена. Общий `AuthSessionManager` атомарно обновляет токены и `SessionState`; подтверждённый отказ refresh немедленно переводит корневой UI в `Unauthenticated`.
- [ ] Устранить ошибочные родительские маршруты в разделе коллекций: `CollectionsGraph` открывает детали и поиск через `Destinations.CATALOG`, а должен сохранять контекст `COLLECTIONS`.
- [ ] Передавать фактический родительский экран в `SearchComposable`; сейчас карточка из поиска всегда открывает детали как часть каталога.
- [ ] Подключить рабочий экран поиска в `SearchGraph`. Сейчас импортирован одноимённый экран-заглушка из `presentation.screens`, а реализованный поиск находится в `presentation.screens.search`.
- [ ] Защитить плеер от пустых источников и озвучек. В `PlayerData` используются `first()`, а в `Playback` — `first()` и `!!`, поэтому корректный ответ API без доступного видео приводит к падению.
- [ ] Запретить выбор недоступных серий и показывать их состояние в `EpisodesPicker`.
- [ ] Исправить переходы между сериями: нельзя вычислять следующую серию простым `episode + 1` и считать `episodesAvailable` номером последней — номера могут иметь разрывы.
- [ ] Устранить гонку сохранения прогресса плеера. Сохранения запускаются параллельно из нескольких callbacks, могут завершаться не по порядку и записать позицию предыдущей серии в новую.
- [ ] Проверить и сделать безопасными персонализированные поля DTO (`favorite`, `my_status`, `my_score` и аналоги), которые API может не вернуть неавторизованному клиенту.
- [ ] Развести DTO прогресса и доменную модель по nullable-полям: ответ требует непустые `sourceProvider` и `voiceoverId`, хотя запрос и модель допускают отсутствие значений.
- [ ] Обрабатывать ошибки JSON/несовместимой схемы ответа, а не только `IOException` и `HttpException`.

## P1 — высокая важность

- [x] Не использовать `runBlocking` для чтения DataStore на каждом сетевом запросе в `AuthInterceptor`. Актуальная пара токенов хранится в volatile-снимке `AuthSessionManager`, загружается при проверке сессии и атомарно обновляется при входе/refresh/выходе.
- [ ] Исключить пароли, коды, access/refresh-токены и тела приватных запросов из debug-логов OkHttp. Отдельно убрать логирование тела ошибок в `MeRepositoryImpl`.
- [ ] Не проглатывать `CancellationException` в репозиториях. Общие `catch (Exception)` должны повторно выбрасывать отмену coroutine.
- [ ] Возвращать вызывающему коду результат `putProgress`, `sendCode` и `logout`, а не только писать ошибку в лог.
- [ ] Исправить классификацию неверного проверочного кода: ответы 400/422 сейчас превращаются в общую `Validation`, поэтому специализированная ошибка недостижима.
- [ ] Защитить формы входа и подтверждения от двойной отправки до того, как `isLoading` попадёт в состояние UI.
- [ ] Сериализовать изменения избранного и статуса на экране деталей и визуально блокировать повторный запрос.
- [ ] Добавить retry-действие на корневой экран ошибки; метод `RootViewModel.retry()` сейчас недоступен пользователю.
- [ ] Реализовать понятные loading/error-состояния в `DetailsComposable` и `PlayerGraph`; пустой экран не должен быть конечным состоянием.
- [ ] Показывать текст реальной ошибки и навигационные действия в `ErrorScreen`.
- [ ] Исправить обновление главного экрана после возврата из деталей: загрузка сейчас вызывается до перехода, а не при возвращении/изменении библиотеки.
- [ ] Показывать кнопку просмотра только при наличии поддерживаемого источника (`hasKodik`/`hasLibria`), предварительно сохранив эти поля при маппинге ответа.
- [ ] Показывать ошибки и повтор загрузки в Paging-списках: initial load, append, refresh и пустой результат.
- [ ] Отображать `ProfileUiState.error` и давать повторить загрузку профиля.
- [ ] Обрабатывать `C.TIME_UNSET` и отрицательные значения до форматирования времени плеера.
- [ ] При выходе из плеера восстанавливать предыдущую ориентацию Activity, а не всегда принудительно portrait.
- [ ] Заменить `popUpTo(0)` конкретным маршрутом/графом, чтобы поведение навигации не зависело от несуществующего destination id.

- [ ] Заменить кликабельный `Text` на семантические кнопки/ссылки либо задать role, label и доступную область нажатия.

- [ ] Добавить прокрутку и адаптивную раскладку на экраны деталей и профиля для маленьких экранов, landscape и крупного шрифта.
- [ ] Убрать фиксированную ширину заголовка серии (200 dp), из-за которой текст обрезается на разных экранах.
- [ ] Подключить к UI выбор источника, озвучки и качества либо удалить неиспользуемые методы до реализации.
- [ ] Определить судьбу неиспользуемых API оценки и рецензии, пустого `SearchUiState` и дублирующего экрана поиска.

## P2 — сборка, зависимости и ресурсы

- [ ] Включить R8 и resource shrinking для release после добавления правил и регрессионных тестов. Текущая release-сборка имеет `isMinifyEnabled = false`.
- [ ] Согласовать JVM toolchain: Java compileOptions используют 17, а Kotlin — 21.
- [ ] Удалить дубли Compose-зависимостей: BOM вместе с лишними фиксированными вариантами, два алиаса Material 3 и два алиаса Compose UI.
- [ ] Проверить и удалить неиспользуемые прямые зависимости: Room и его plugin/compiler, Security Crypto, AppCompat, Material Views, Image Cropper, Google Fonts, Media3 UI и runtime tracing.
- [ ] Исследовать предупреждение Moshi codegen о deprecated KAPT, несмотря на конфигурацию KSP.
- [ ] Разобрать 73 неиспользуемых ресурса из lint: не удалять автоматически, а сверить с планируемыми экранами.
- [x] Устранить 18 конфликтов XML/PNG: все 450 density PNG удалены, а код переведён на канонические vector drawable `_24` с сохранением прежних размеров через `Modifier.size`/компоненты.
- [x] Удалить девять групп PNG с идентичным содержимым. В исходных ресурсах и остальном репозитории вне генерируемых каталогов PNG больше нет.
- [ ] Выбрать единый источник дизайн-токенов: сейчас цвета/размеры частично дублируются между XML и Compose.
- [ ] Обновлять AGP, Kotlin, Compose, Hilt, Media3, Paging и AndroidX небольшими отдельными шагами с тестами, а не одним массовым изменением.
- [ ] Дополнить правила резервного копирования исключением auth DataStore для `device-transfer`; текущая конфигурация исключает его только из cloud backup.

## Результаты базовой проверки до исправлений

- `testDebugUnitTest`, `lintDebug` и `assembleDebug` завершались успешно.
- `lintRelease` и `assembleRelease` завершались успешно.
- Выполнялся только один содержательный unit-тест; instrumented-тесты не запускались из-за отсутствия подключённого устройства.
- После перехода на векторные иконки Android Lint сообщает 88 предупреждений: 73 неиспользуемых ресурса и 15 предупреждений о версиях инструментов/зависимостей. Категории `IconXmlAndPng` и `IconDuplicates` имеют нулевой результат.
- Все 18 канонических иконок имеют размер и viewport 24×24. Использовавшиеся размеры 14, 18, 20 и 24 dp сохранены на уровне Compose-компонентов.
